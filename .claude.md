# Global Optimization via Softmin Energy Minimization

## Project Overview

PhD research on non-convex optimization in high dimensions using gradient-based swarm methods.
The project introduces a Softmin Energy interaction $J_\beta(\mathbf{x})$ that couples particles
through their relative objective values, achieving provably faster transitions between local
minima than overdamped Langevin dynamics.

**Paper title:** *Global Optimization via Softmin Energy Minimization*

**Key research focus:**
- Gradient flow dynamics under the Softmin Energy interaction
- Noisy dynamics and SDE analysis (Euler-Maruyama discretization)
- Eyring-Kramers-type estimate for effective potential barriers (Kramers' law)
- Convergence-rate comparison against overdamped Langevin dynamics
- Numerical validation against Simulated Annealing, Gradient-Aware CBO, and Gradient-Enhanced PSO

## LaTeX Conventions and Structure

### Core Notation

**Vectors and Matrices:**
- Particles: $\mathbf{x}_i$ or $x_i$; population $\mathbf{x} = (x_1, \dots, x_n)$, $x_i \in \mathbb{R}^d$
- Objective function: $f: \mathbb{R}^d \to \mathbb{R}$
- Gradient: $\nabla f$, $\nabla J_\beta$ (always with $\nabla$, never $\partial$)
- Step size / learning rate: $\eta$ (code: `learning_rate`)
- Noise level: $\sigma$ (standard deviation-type diffusion coefficient)
- Inverse temperature: $\beta$; Gibbs weight of particle $k$: $w_k = e^{-\beta f(x_k)} / \sum_j e^{-\beta f(x_j)}$

**Softmin Energy** (the central object — note this is a *weighted average*, not a log-sum-exp):
$$J_\beta(\mathbf{x}) = \sum_{i=1}^n w_i\, f(x_i), \qquad w_i = \frac{e^{-\beta f(x_i)}}{\sum_{j=1}^n e^{-\beta f(x_j)}}$$
The paper explicitly contrasts this with the *different* log-sum-exp/free-energy functional
$F_\beta(\mathbf{x}) = -\beta^{-1}\log\sum_i e^{-\beta f(x_i)}$ (whose gradient reduces to plain
weighted gradient descent, $w_k \nabla f(x_k)$, and lets low-weight particles stagnate). The
Softmin functional's gradient instead carries a sign-changing effective learning rate — see
"Softmin Energy and Core Algorithm" below. **Do not conflate the two formulas.**

**Stochastic dynamics (Euler-Maruyama discretization used in code):**
```latex
d\mathbf{x}_i(t) = -\nabla J_\beta(\mathbf{x}_i(t))\,dt + \sigma\,dW_i(t)
```

### How each figure is produced

- **1D double well, exit time from the maximizing regime** — driver:
  `run_theory_verification.py` -> `results/softmin_static_double_well_init0_{delta}_{noise}.pkl`
  -> notebook cell under "Exit time from the maximizing regime".
- **1D double well, mean entry time vs. barrier height** — driver:
  `run_experiments_resumable.py` (`exp_name='double_well'`) ->
  `results/{softmin,sa,cbo,pso}_double_well_{delta}.pkl` -> notebook cell under
  "1 Dimensional Double Well Potential", rendered via `viz.plot_entry_time_comparison`. The
  SoftMin-Decay series for this figure reads `results/softmin_decay_highermaxsteps_double_well_{delta}.pkl`
  — a differently-named file that `run_experiments_resumable.py`'s own reconstruction step does
  **not** currently regenerate (it would write plain `softmin_decay_double_well_{delta}.pkl`
  instead). This mismatch pre-dates this refactor; if you need to regenerate that specific series,
  either rename the reconstructed file or add a `highermaxsteps`-suffixed run — check with the
  user before changing the filename convention either driver relies on.
- **2D quadruple well, mean entry time vs. barrier gap** — same driver
  (`exp_name='quadruple_well'`) -> `results/*_quadruple_well_{A}.pkl` / `*_highermaxsteps_quadruple_well_{A}.pkl`

## Code Conventions

### Module responsibilities

- **`simulations.py`** — `Simulation` (ABC: init/reset/run/`first_entry_time`/`plot` dispatch) and
  the 5 concrete dynamics. Behavior here backs the paper's numerical claims — changes should be
  bit-identical unless deliberately fixing a bug (see Sensitivity below).
- **`potentials.py`** — pure functions returning `{'f_vec', 'f_grad_vec', 'particle_init', 'set',
  'bounds', ...}` dicts. All are built with `sympy` (symbolic derivative) then `lambdify`'d and
  `np.vectorize`'d, except `high_dim_ackley_function_setting`, which is hand-vectorized NumPy for
  speed at high `d`.
- **`viz.py`** — `plot_simulation(sim, ...)` (used by `Simulation.plot()`) and
  `plot_entry_time_comparison(x, results_dir, series, ...)`, the shared errorbar-plot helper used
  by all three notebook comparison figures.
- **`experiments.py`** — `run_resumable_pool` (resumable CSV + `mp.Pool.imap_unordered`, used by
  all three `run_*.py` drivers) and `reconstruct_pkl_files_from_csv` (rebuilds the per-condition
  `.pkl` files the notebook reads from the flat CSV log).

### Function signatures
- Type hints on public functions (array shapes matter for correctness).
- New algorithm classes should subclass `Simulation` and implement `step()`; reuse
  `first_entry_time`/`run`/`reset` from the base class rather than re-implementing them.

### Numerical stability
- Softmin weights and energy (`SoftminEnergyAdagrad._get_softmin_weights` /
  `_compute_softmin_energy`) and the CBO consensus point
  (`GradientAwareCBO._compute_consensus_point`) both shift by `np.min(values)` before
  exponentiating — never remove that shift, it's what prevents `exp(-beta * f)` overflow for
  large `beta`.

## Notebook & Experiment-Running Conventions

There is **one** analysis notebook, `src/ICML_submission_code.ipynb`. It contains **no simulation
logic** — it only loads `results/*.pkl` and renders the paper's comparison figures via
`viz.plot_entry_time_comparison`. Actually *generating* those `.pkl` files is done by running the
three `run_*.py` drivers on the cluster (see harness in `experiments.py`); each is independently
resumable (safe to kill and re-launch — it skips `(experiment, parameter, seed)` combinations
already present in its CSV log).

### Reproducing a figure
1. Rerun the relevant `run_*.py` driver on the cluster (it appends to its CSV and regenerates the
   matching `.pkl` files via `reconstruct_pkl_files_from_csv` when it finishes, or can be re-run
   standalone against an existing CSV).
2. Re-run the corresponding notebook cell (each cell is self-contained: builds its `x`/`params`
   sweep, then calls `plot_entry_time_comparison`).

### Notebook testing workflow
- Since there's no pytest suite, validate notebook edits by executing all cells top-to-bottom
  against the existing `results/` data (headless: `matplotlib.use('Agg')` avoids blocking on
  `plt.show()`) and confirming no exceptions and visually-sane plots.

## Sensitivity: Don't Touch (without discussing first)

**Code-critical:**
- The `-np.min(values)` numerical-stability shift before any `exp(-beta * ...)` in
  `simulations.py`.
- The noise scaling `sqrt(2 * D) * dW` / `sqrt(2 * D * eta)` pattern in `GaussianDiffusion` and
  `SimulatedAnnealing` — this is what makes the discretization match the SDE's diffusion term.
- `SoftminEnergyAdagrad`'s `beta_decay` direction: it **decreases** $\beta$ over time
  (`self.beta *= self.beta_decay` with `beta_decay < 1`). This matches the paper's "Dynamic
  Annealing" remark, which calls for decaying $\beta \to 0$, not increasing it.
- Random seeds in the `run_*.py` drivers (`np.random.seed(seed * 1000)`, `seed in range(100)`) —
  changing the seeding scheme invalidates resumability against existing CSV logs.

**Paper-critical:**
- The distinction between $J_\beta(\mathbf{x}) = \sum_i w_i f(x_i)$ (this paper's Softmin
  functional) and $F_\beta(\mathbf{x}) = -\beta^{-1}\log\sum_i e^{-\beta f(x_i)}$ (the log-sum-exp
  functional the paper explicitly argues against) — don't merge or confuse these in docstrings or
  comments.
- CBO/PSO being excluded from the quadruple-well figure — a cited experimental finding
  (variance collapse), not a TODO.

**Experimental:**
- Benchmark parameters (double-well `delta` range, quadruple-well `A` range, Ackley dimensions)
  — sweep ranges live in each `run_*.py`'s `if __name__ == '__main__':` block; keep in sync with
  Appendix "Experimental Details and Hyperparameters" if changed.

## Dependencies: Critical Pinning

`src/requirements.txt` pins NumPy/SciPy/sympy/matplotlib versions because numerical behavior can
shift subtly between minor versions and the published convergence/entry-time figures must stay
reproducible. Only bump a pinned version if you need a specific new feature, and re-render the
notebook's figures against existing `results/` data afterward to confirm no visual drift.

## When Reviewing Code

**For new functions:** check against the relevant paper section reference; state mathematical
assumptions explicitly; verify numerical stability (log-domain / shifted-exp) is handled.

**For refactoring:** confirm behavior is preserved for any function feeding a currently-published
figure (a quick same-seed before/after comparison on `Simulation.step()`/`.run()` output is enough
— see how this was verified during the `swarm_particle_optimization.py` -> `simulations.py` split);
prefer reusing `Simulation`/`experiments.py` machinery over new one-off scripts.

**For bug fixes:** state what the mathematical or logical error was, whether it could have
affected already-published figures, and whether the affected `results/*.pkl` need regenerating on
the cluster.
